## 2026-10-13 (D1) LM Studio 연동

환경: LM Studio 0.4.25, `qwen/qwen3.6-35b-a3b`(MLX 4-bit), `text-embedding-kure-v1`, langchain-core 1.6.10, langchain-openai 1.7.1, openai 3.29.0, Python 3.12.14. 확인 명령은 `uv run sfqa smoke`.

- **thinking 끄기:** 요청 본문에 `reasoning_effort: "none"`을 `extra_body`로 넣으면 json_schema 응답이 content로 온다. reasoning은 0자였다.
- **길이 제한:** langchain-openai 1.7.1은 `max_tokens`를 `max_completion_tokens`라는 이름으로 보낸다. LM Studio는 이 이름을 지킨다(8로 두자 7토큰에서 `length`로 멈췄다).
- **잘린 응답:** json_schema를 붙이면 OpenAI SDK의 구조화 출력 경로를 타서, 잘린 응답이 `LengthFinishReasonError`로 온다. `LiveClient`가 이 예외를 잡아 `truncated`로 기록한다(`tests/test_llm.py`).
- **임베딩:** `check_embedding_ctx_length=False`면 입력이 문자열로 나간다. 차원은 1024. 비슷한 문장 쌍 0.871, 다른 문장 0.296.
- **속도:** 출력 약 300토큰에서 초당 약 90토큰. 호출마다 고정 지연이 약 2.5초 있다. 입력이 긴 실제 질문의 속도는 D6에 다시 잰다.
- **구조화 출력 방식(D1):** `with_structured_output` 대신 `response_format`(json_schema, strict)을 직접 붙이고, 앞에 붙은 `<think>…</think>`를 지운 뒤 직접 해석한다. 해석 실패와 잘림을 예외가 아닌 기록으로 남기기 위해서다.

## 2026-10-13 (D6) 답변 체인과 코드 검증

확인 명령: `uv run pytest`(106개 통과), `uv run sfqa ask --upto <N> "<질문>" [--condition C0~C4]`.

- **구성:**
  - `schema.py`: 답 형식(status, answer, quotes[{chapter, text}]). json_schema strict로 보낸다.
  - `prompts.py`: 기본(C1, C2), 가드(C3, C4), 검색 없음(C0)
  - `answer.py`: LCEL 체인. 검색 → 요청 → 카세트를 거친 모델 호출 → 해석 → 검증
  - `verify.py`: 인용 검증, 인물 가드, 고정 거절문
  - C4는 C3와 똑같은 요청을 보낸다(카세트 키가 같다). 그래서 모델 호출이 늘지 않는다.
- **인용 검증:**
  - 정규화: 따옴표 접기, NFKC, 한자 괄호·× 제거, 공백 무시
  - 검증 결과:
    - 적힌 장에 있으면 통과
    - 다른 N장 이하 장에 있으면 장 번호를 고쳐 통과
    - N장 뒤에만 있으면 버리고 L1로 표시
    - 어디에도 없으면 버림
  - 8자 미만은 근거로 보지 않는다.
  - 발췌 밖이지만 N장 이하 원문에 있는 인용은 남기되 '기억에서 옮김'으로 표시한다.
- **실제 실행 (qwen3.6-35b-a3b, k=18):**
  - 입력 약 8천 토큰, 출력 20~300토큰에 호출당 **약 6~7초**다.
  - 첫 호출만 54초였다. 모델을 다시 올리는 시간으로 보인다.
- **관찰 1: 사례**
  - "초봉이가 일하는 곳은 어디인가?"
    - 3장까지: 제중당. 2장 인용 2개가 검증을 통과했다.
    - 1장까지: 모델이 답하지 않아 "1장까지는 나오지 않습니다."가 나갔다.
  - "태수는 어떻게 되나?"
    - 9장까지, C2: 답하지 않음
    - 9장까지, C4: 9장까지의 처지(횡령, 빚)로 답했다. 10장의 죽음은 흘리지 않았다.
    - 10장까지: 죽음 장면을 검색하지 못해 처지만 답했다(검색에서 놓친 f10-1과 같은 원인).
    - C0: 모르겠다고 답했다.
- **관찰 2: B 문항의 "답함"이 스포일러는 아니다.** "어떻게 되나"류 B 문항은 N장까지의 처지로 정당하게 답할 수 있다. 채점에서 B의 "답함"은 누출(L1~L3, 사람 판정)과 따로 센다. 스포일러 판단은 누출로 한다.
- **관찰 3: 답이 길다.** "짧게 답한다"를 잘 지키지 않는다(최대 306토큰). 프롬프트는 dev 문항으로만 고친다(D8).

- **인물표:** kiwipiepy 고유명사 3회 이상(태평천하 47, 상록수 32, 운현궁의 봄 164, 무정 92). 사람 검토 전이다.
- **C4 강화:** N장 뒤에만 있는 인용이 하나라도 있으면 답하지 않는다. 「탁류」 test를 카세트로 재채점한 결과, Claude와 qwen3.6 모두 강화 전과 결과가 완전히 같았다.
- **첫 화면 문구:** 작품마다 예시 질문 3개와 소개 한 줄을 앞 장(3장, 「무정」은 5장)만 읽고 만들었다. 다른 에이전트가 반박 검증했고, 근거 인용 12개가 앞 장 원문에 있는 것을 코드로 확인했다.
- **화면:** 첫 화면에 작품 카드를 둔다. 작품 화면은 기존 대화 화면에 "← 다른 소설"을 더했다. 30장이 넘으면 번호 입력과 막대로 장을 고른다. 워드마크는 작품 제목 길이에 맞춰 줄인다.

## 2026-10-14 코드 리뷰 반영 (main 이후 변경 전체)

방법: 네 관점(정확성, 스포일러 안전, 보안, 단순화)으로 리뷰어 4명이 찾고, 관점마다 다른 에이전트가 반박 검증했다. 지적 14개 중 12개가 확인됐다.
확인 명령: `uv run pytest`(254개 통과).

- **정확성**
  - 「무정」(묶음 페이지)을 다시 받으면 KeyError가 났다. 고쳤고 가짜 위키문헌으로 두 번 받기 테스트를 더했다(tests/test_fetch.py).
  - 질문을 기다리는 사이 작품을 바꾸면 비교 요청이 다른 작품으로 가거나 화면이 멈췄다. 질문할 때의 작품을 고정하고 try/finally로 풀었다. 늦게 온 장 목록이 지금 작품을 덮지 않게 했다.
  - '*' 장면 구분을 지키려다 ':' 들여쓰기 표시까지 본문에 남겨, 여러 줄 인용이 검증에서 떨어졌다. 내용 없는 '*' 한 줄만 남기도록 고쳤다. 「상록수」를 다시 정제하고 색인을 다시 만들었다. 「탁류」 본문은 그대로다.
- **스포일러 안전**
  - 「탁류」 예시 질문에 6장 인물(명님이)이 3장 기본 화면에 보였다. 예시를 1~2장 사실로 바꿨다.
  - 예시마다 '몇 장부터 보여 줄지'(답이 있는 장, 질문에 든 인물의 첫 등장 장 가운데 늦은 쪽)를 서버가 계산하고, 화면은 고른 장 이하의 예시만 보여 준다.
  - 「무정」 소개 문구의 영채(4장)를 뺐다. 첫 화면 소개에는 1장 인물만 쓰도록 테스트로 막는다.
  - 자동 인물표가 주요 인물을 놓쳤다(「무정」 병욱 91장, 「상록수」 정근 11장 등). 성을 뗀 이름을 별칭으로 자동 추가하고, 놓친 이름은 work.json의 extra_entities로 더했다. 인물표에 들어갔는지 테스트로 확인한다.
- **보안·비용**
  - IPv6는 /64 대역으로 접어 센다. 주소만 바꿔 IP별 상한을 피하지 못하게 했다.
  - 동시 요청이 같은 '전체 하루' 칸을 갱신해 생기는 TransactionConflict는 짧게 쉬었다가 3번까지 다시 시도한다.
  - **배포 IAM 정책의 권한 상승 경로(높음)**: 권한 경계 정책(`infra/boundary-policy.json`)과 경계를 강제하는 새 배포 정책을 준비했다. IAM 콘솔에서 사용자가 적용해야 한다(`docs/deploy-plan.md` "권한 경계 적용"). 그 전까지 템플릿의 경계 파라미터는 비워 둔다.
- **단순화**
  - 완결 확인을 머리말·꼬리말 둘 다에서 '다음'으로 본다. 그런 틀이 없으면 '확인 못 함'(None)으로 적는다.
  - 옛 경로를 쓰던 정답지 스크립트 두 개를 고쳤다.
  - 색인 오류 안내에 작품과 실행 방식을 넣었다.
  - claude.py의 낡은 설명을 고쳤다.
- **반박된 지적**
  - /api/chapters가 아직 안 읽은 장 제목까지 보낸다는 지적은 기존(main)에도 있던 동작이라 이번 범위에서 뺐다. 화면에서는 가린다.
  - 문서만 낡은 지적 하나(claude.py)는 동작에 영향이 없어 반박됐지만, 설명은 고쳤다.
