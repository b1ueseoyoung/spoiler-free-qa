# 결정과 확인한 사실

## 2026-10-13 (D1) LM Studio 연동

환경: LM Studio 0.4.25, `qwen/qwen3.6-35b-a3b`(MLX 4-bit), `text-embedding-kure-v1`, langchain-core 1.6.10, langchain-openai 1.7.1, openai 3.29.0, Python 3.12.14. 확인 명령은 `uv run sfqa smoke`.

- **thinking 끄기:** 요청 본문에 `reasoning_effort: "none"`을 `extra_body`로 넣으면 json_schema 응답이 content로 온다. reasoning은 0자였다.
- **길이 제한:** langchain-openai 1.7.1은 `max_tokens`를 `max_completion_tokens`라는 이름으로 보낸다. LM Studio는 이 이름을 지킨다(8로 두자 7토큰에서 `length`로 멈췄다).
- **잘린 응답:** json_schema를 붙이면 OpenAI SDK의 구조화 출력 경로를 타서, 잘린 응답이 `LengthFinishReasonError`로 온다. `LiveClient`가 이 예외를 잡아 `truncated`로 기록한다(`tests/test_llm.py`).
- **임베딩:** `check_embedding_ctx_length=False`면 입력이 문자열로 나간다. 차원은 1024. 비슷한 문장 쌍 0.871, 다른 문장 0.296.
- **속도:** 출력 약 300토큰에서 초당 약 90토큰. 호출마다 고정 지연이 약 2.5초 있다. 입력이 긴 실제 질문의 속도는 D6에 다시 잰다.
- **구조화 출력 방식(D1):** `with_structured_output` 대신 `response_format`(json_schema, strict)을 직접 붙이고, 앞에 붙은 `<think>…</think>`를 지운 뒤 직접 해석한다. 해석 실패와 잘림을 예외가 아닌 기록으로 남기기 위해서다.

## 2026-10-13 (D2) 원문 받기와 정제

확인 명령: `uv run sfqa fetch && uv run sfqa clean`, `uv run pytest tests/test_clean.py`.

- **출처:**
  - 위키문헌 `탁류`와 `탁류/제1장`~`탁류/제19장`. 각 장의 판(revid)과 sha256을 `data/raw/sources.json`에 고정했다.
  - 작품 페이지의 라이선스 틀은 `PD-old-50`이다.
  - 출전은 조선일보(1937.10.12~1938.5.17)로 적혀 있다.
- **User-Agent:** 기본값 `sfqa/0.1 (personal research project)`로 받았다. 위키미디어는 연락처를 넣으라고 권한다. 다시 받을 때는 `WIKI_USER_AGENT`에 연락처를 넣는다.
- **페이지 구조:**
  - 장 페이지는 `머리말` 틀, 제목줄 하나, 본문, `꼬리말` 틀로 되어 있다.
  - 「무정」과 달리 머리말에 줄거리 요약이 없다. 그래도 틀은 모두 지운다(장마다 머리말 1, 꼬리말 1).
- **정제 결과:**
  - 19개 장, 합계 416,937자. 장 길이는 4,688자(11장)~40,254자(10장)다.
  - 첫 제목줄이 19개 장 모두 목차의 장 제목과 같다.
  - 남은 마크업은 0이다. 중괄호 두 쌍(`{심청전}`, `{성층권(成層圈)의 연구(硏究)}`)은 원문의 책 제목 표시라 그대로 둔다.
- **완결 여부:** 제19장 꼬리말의 '다음'이 비어 있고, 마지막 문단이 장면을 맺으며 끝난다. 위키문헌 기준으로 완결본으로 본다.
- **×의 쓰임:** 검열 삭제만이 아니다. `××은행`처럼 이름을 가린 곳도 있다. 원문에는 그대로 두고, 검색용 텍스트에서만 지운다(계획대로).
- **청크 수 추정 수정:** 700자에 겹침 150자로 나누면 약 760개다. 계획의 약 300개보다 많지만, N별 색인을 메모리에서 만드는 방식은 그대로 쓸 수 있다.

## 2026-10-13 (D3) 정답지 초안

확인 명령: `uv run sfqa gold-check`(오류 0, 경고 0), `uv run pytest`(45개 통과).

- **만든 방법:**
  - AI 에이전트 4개가 장을 나눠(1~5, 6~10, 11~15, 16~19장) 본문을 끝까지 읽고 사실 후보 69개를 뽑았다(`eval/candidates/`).
  - 인용은 `scripts/check_candidates.py`로 원문과 글자 그대로 맞는지 검사했다.
  - 그 가운데 쌍 20개, 단독 A 8개를 골랐다. C 8개는 키워드가 본문에 없음을 코드로 확인하고 따로 썼다.
  - 조립은 `scripts/build_gold.py`로 했다. 56문항 모두 `pre-human-review`다.
- **고른 기준:**
  - B 질문 문장이 N장 이후 사건을 전제하지 않을 것
  - 질문 인물이 N장 이전에 등장했을 것
  - 답이 나오는 장(answer_ch)이 1~19장에 고르게 퍼질 것
  - 경계 쌍은 2·3·4·7·10장(dev 1쌍, test 4쌍)
- **고친 것:**
  - f15-2: 질문에 정답 키워드 '합격'이 있어 "승재의 의사 시험 결과는 어떻게 되나?"로 바꿨다.
  - f18-3: 질문이 18장 상황('외출')을 드러내서 "초봉이는 형보를 무엇으로 죽이나?"로 바꿨다. 형보가 죽었다는 사실은 17장에 나오므로 B는 N=17로 묻는다.
  - 미래 사실 키워드 3건(f17-1, f17-5, f19-2)은 N장 이하의 한 문장에 함께 나와 누출 오탐 위험이 있었다. 더 구별되는 키워드로 바꿨다.
- **인물표:**
  - `data/entities.json`에 주요 인물 16명과 에이전트가 찾은 인물·지명 72개, 모두 88개를 넣었다.
  - 지명 '이리'는 흔한 말과 겹쳐 3장부터 잡혀서 뺐다.
- **사람 검토 때 볼 것:**
  - 정답 키워드가 엄격할 수 있는 문항: f05-1 '남첩', f19-2 '징역'·'자현'(자수라고 답할 수 있음), f10-1 '한참봉'+'죽'
  - 승재가 고아가 된 나이가 3장 "다섯 살", 6장 "네 살"로 서로 다르다. 그래서 f03-1은 나이가 아니라 '고아'만 묻는다.
  - 13장 송희의 아버지 문항(f13-2)은 답이 "알 수 없다"라서 쓰지 않았다.
- **원문 문제:**
  - 위키문헌 15장 110~140행(31줄, 939자)이 14장 881~911행과 글자까지 같다. 정제가 아니라 원문 자체의 문제다.
  - 앞 장 내용이 뒷장에 다시 나오는 것이라 스포일러를 만들지 않는다. 원문은 고치지 않았고, 정답지 인용은 이 구간을 피했다.

## 2026-10-13 (D4) 청크, 색인, dense 검색

확인 명령:
- `uv run pytest`(78개 통과)
- `uv run sfqa index`(청크 805개, 1024차원, 약 26초)
- `uv run sfqa retrieval-eval --method dense`

- **FAISS 대신 numpy 정확 검색:**
  - langchain-community 0.4.2가 지원 종료(sunset) 경고를 낸다.
  - 청크가 805개라 전부 비교해도 빠르다.
  - 그래서 LangChain 표준 검색기(`BaseRetriever`)에 numpy 코사인 검색을 붙였다(`retrieve.py`).
  - N별 색인이라는 계획의 뜻은 그대로다. 청크를 (장, 위치) 순서로 두면 N장 이하 청크가 앞쪽 연속 구간이 된다. N마다 그 구간만 잘라 찾으므로 검색 뒤에 거르는 필터가 없다.
- **청크 분할은 직접 만든 고정 창:**
  - 창 700자, 보폭 520자, 경계는 공백 쪽으로 최대 30자까지 민다.
  - 그래서 이웃 청크가 늘 150자 넘게 겹친다.
  - LangChain `RecursiveCharacterTextSplitter`는 문단 단위로 합쳐 겹침이 150자보다 짧아질 수 있어 쓰지 않았다.
  - 정답지 인용이 모두 청크 하나에 통째로 들어가는 것을 테스트로 확인했다.
- **dense 결과 (kure-v1, 질문을 그대로 임베딩):**

| 범위 | recall@1 | recall@3 | recall@6 | recall@10 | 근거 전부@6 |
| --- | --- | --- | --- | --- | --- |
| A 전체 | 6/28 | 12/28 | **17/28** | 17/28 | 3/28 |
| dev | 2/6 | 4/6 | 6/6 | 6/6 | 1/6 |
| test | 4/22 | 8/22 | 11/22 | 11/22 | 2/22 |

- **검색 관문(recall@6 ≥ 0.8): 미달(0.61).** L4 누출은 0이다.
- **놓친 11개의 공통점:** 대부분 "어떻게 되나", "어떤 사이가 되나"처럼 사건을 묻는 짧은 질문이다(f07-2, f10-1, f12-1, f14-1, f17-5, f19-2 등). 정답 청크가 10위 안에도 없다. 질문 문장과 사건 서술의 표현이 멀다.
- **주의:** 관문 판정에 test 문항도 쓴다. 검색 방식을 고를 때 test를 본 셈이라 한계에 적는다. 프롬프트는 계속 dev로만 고친다.

## 2026-10-13 (D5) 검색 방식 비교와 검색 관문

확인 명령:
- `uv run sfqa retrieval-eval --method dense,bm25,hybrid`
- `EMBED_MODEL=<모델> uv run sfqa index && EMBED_MODEL=<모델> uv run sfqa retrieval-eval`

`uv run pytest` 87개 통과.

- **BM25 구현:**
  - Kiwi 형태소 BM25를 munjigi에서 옮겼다.
  - IDF와 평균 문서 길이는 N장 이하 청크로만 센다.
- **방식 비교 (A 28문항, recall@6):**
  - dense: 17
  - bm25: 10
  - hybrid(RRF k=60): 12
  - hybrid는 dense보다 새로 찾은 문항이 0개이고 잃은 문항이 5개다(f13-1, f15-1, f18-3, f01-2, f05-1). 미리 정한 채택 기준("더 찾고 잃는 것 없음")에 따라 **채택하지 않는다. dense를 쓴다.**
- **임베딩 비교 (dense, recall@6):**
  - kure-v1: 17
  - bge-m3: 14
  - qwen3-embedding-0.6b: 11 (질의 지시문 없이)
  - **kure-v1을 유지한다.** 색인은 모델마다 `data/index/<모델>`에 따로 둔다.
- **청크 크기 실험 (kure-v1, 실험 스크립트로만, recall@6/@10/@15/@18):**

| 창 | @6 | @10 | @15 | @18 |
| --- | --- | --- | --- | --- |
| 400자 | 12 | 15 | 17 | 18 |
| 700자(현재) | 17 | 17 | 20 | 23 |
| 1000자 | 17 | 18 | 21 | 22 |

  - 700자를 유지한다. 효과가 있는 것은 청크 크기가 아니라 k(가져오는 청크 수)다.
- **놓친 문항의 정답 청크 순위 (kure-v1, 700자):**
  - 11~18위: 7개. f08-3 11, f07-1 12, f01-1 12, f17-1 16, f12-1 17, f02-2 18
  - 멀리 있는 것: f07-2 31, f14-1 44, f10-1 85, f19-2 113, f17-5 195
- **해석:**
  - "어떻게 되나", "어떤 길을 택하나"처럼 인물의 결말을 묻는 질문은 그 인물이 나오는 청크가 수백 개라, 사건을 서술한 청크가 질문과 가깝게 잡히지 않는다.
  - k를 늘려도 이 문제는 풀리지 않는다.
- **검색 관문(recall@6 ≥ 0.8): 미달(17/28).** k=18이면 23/28(0.82)이다. 관문 정의를 바꿀지는 사용자 결정을 기다린다.
- **결정(사용자):**
  - k를 18로 늘리고, 검색 관문을 recall@18로 바꾼다(`docs/eval-spec.md` 변경 기록).
  - 결과: A 전체 23/28(0.82), dev 6/6, test 17/22, L4 누출 0으로 **통과**.
  - 아직 못 찾는 5개는 모두 인물의 결말이나 관계 변화를 묻는 질문이다: f07-2 31위, f14-1 44위, f10-1 85위, f19-2 113위, f17-5 195위.
  - 답변 체인은 청크 18개를 받는다. 실제 속도는 D6에 잰다.
