# 평가 기준 (2026-10-13 확정)

이 문서는 만들기 전에 정한다. 프롬프트나 검색을 고친 뒤에 기준을 바꾸지 않는다. 바꿔야 하면 바꾼 날짜와 이유를 아래 "변경 기록"에 남긴다.

## 용어

- **장:** 「탁류」의 19개 장. 회차로 본다.
- **N:** 독자가 읽은 마지막 장(1~19). 시스템은 1~N장만 근거로 쓴다.
- **답이 처음 나오는 장(answer_ch):** 정답을 확정할 수 있는 문장이 처음 나오는 장.

## 시스템 출력

- 상태는 `answered`와 `not_found` 두 가지뿐이다. "아직 안 나옴"이라고 말하면 뒷이야기가 있다는 사실 자체가 새기 때문이다.
- `not_found`이면 모델 문장을 버리고 코드가 고정 문구를 낸다.
  - N<19: "N장까지는 나오지 않아요."(2026-10-14 대화체로 바꿈. 처음에는 "나오지 않습니다")
  - N=19: "작품에 나오지 않아요."
- `answered`이면 답과 인용(장 번호, 원문 구절)을 낸다. 인용은 코드 검증을 통과한 것만 남긴다.

## 문항 유형

| 유형 | 조건 | 기대 결과 |
| --- | --- | --- |
| A 답 있음 | answer_ch ≤ N | `answered`, 정답, 인용 장 ≤ N |
| B 스포일러 미끼 | answer_ch > N | `not_found`, 누출 없음 |
| C 작품에 없음 | 본문 어디에도 없음. 연재 매체·연도, 작가 생애처럼 모델은 알 수도 있는 것을 포함한다 | `not_found` |

## 문항 구성 (56문항)

| 묶음 | dev | test | 합계 |
| --- | --- | --- | --- |
| 같은 사실을 두 N으로 묻는 쌍(A 하나 + B 하나) | 4쌍(8) | 16쌍(32) | 20쌍(40) |
| 단독 A | 2 | 6 | 8 |
| C | 2 | 6 | 8 |
| 합계 | 12 | 44 | 56 |

- 쌍 20개 가운데 10개는 경계 문항이다. 5개는 N = answer_ch(A), 5개는 N = answer_ch − 1(B)로 묻는다. `<`와 `<=` 실수를 잡기 위해서다.
- answer_ch는 1~19장에 고르게 퍼뜨린다.
- dev는 프롬프트와 검색을 고칠 때만 쓴다. test는 최종 실행에만 쓴다.

## 작성 규칙

- B 질문 문장에 미래 정보를 넣지 않는다. 예: "태수는 누구에게 죽나?"는 안 되고 "태수는 어떻게 되나?"로 묻는다.
- 질문에 나오는 인물은 N장 이전에 등장한 인물이어야 한다.
- 근거 인용은 150자 이하로, 정제한 본문에 글자 그대로 있어야 한다.
- 문항마다 `review` 값을 둔다. AI 초안은 `pre-human-review`, 사람이 확인하면 `human-reviewed`.

### 문항 필드 (`eval/questions.jsonl`)

| 필드 | 뜻 |
| --- | --- |
| `id`, `pair_id`, `split` | 문항 id, 쌍 id(단독이면 null), dev 또는 test |
| `type` | A, B, C |
| `n` | 독자가 읽은 마지막 장 |
| `question` | 질문 |
| `gold_answer` | 사람이 읽을 정답 문장 |
| `answer_keys` | 정답 판정 키워드. 정규화한 뒤 모두 답에 있으면 자동 정답 |
| `evidence` | `[{chapter, quote}]`. A의 근거, B의 미래 근거 |
| `answer_ch` | 답이 처음 나오는 장(C는 null) |
| `future_facts` | `[{chapter, keys}]`. N장 이후 사실의 키워드 조합(누출 탐지용) |
| `boundary` | 경계 문항이면 true |
| `review` | pre-human-review 또는 human-reviewed |

## 정답지 검사 (`sfqa gold-check`, 모델 없이)

- 근거 인용이 해당 장 본문에 글자 그대로 있다.
- A는 근거 장 ≤ N, B는 answer_ch > N이다.
- 질문에 나오는 인물의 첫 등장 장 ≤ N이다.
- C의 키워드가 본문 어디에도 없다.
- future_facts 키 조합이 N장 이하 본문의 한 문장에 함께 나오면 경고한다(누출 오탐 위험).

## 실험 조건

| 조건 | 검색 범위 | 가드 | 보는 것 |
| --- | --- | --- | --- |
| C0 | 검색 없음 | 프롬프트 | 모델이 기억만으로 얼마나 알고 흘리는지 |
| C1 | 19장 전체 | 없음 | 필터가 없을 때의 누출 상한 |
| C2 | N장 이하 | 없음 | 문맥에 미래가 없으므로, 남은 누출은 모델 기억 누출 |
| C3 | N장 이하 | 프롬프트("발췌 밖 지식 금지, 이후 전개 암시 금지") | 프롬프트 가드 효과 |
| C4 | C3 기록 재사용(모델 호출 0회) | 프롬프트 + 코드 검증(인용 검증, 인물 가드, 고정 거절문) | 최종 시스템에 남는 누출 |

## 판정

**유형별 결과**
- A: 정답 / 오답 / 놓침(`not_found`) / 형식 실패(해석 실패, 잘림)
- B: 보류(`not_found`) / 답함
- C: 보류 / 근거 없는 답

**인용**
- 검증 통과 인용 수
- 인용 장이 정답 근거 장과 같은지

**누출 (검색기와 따로 판정, A의 답에도 적용)**
- L1: 인용이 N장 이후 본문에만 글자 그대로 있다(원문 암기).
- L2: 문항의 future_facts 키 조합이 정규화 후 답에 모두 나온다.
- L3: N장 이후에 처음 나오는 인물·지명이 답에 나온다. 첫 등장 장은 코드로 계산하고 별칭은 사람이 검토한다.
- L4: 검색된 청크의 장을 메타데이터가 아니라 본문 내용으로 찾았을 때 N보다 크다.
- 이름이나 키워드 없이 풀어 쓴 누출은 자동으로 못 잡는다. `review.csv`에서 사람이 본다.

## 집계

- 유형 × 조건별 개수(k/n)로만 낸다. 하나의 정확도로 합치지 않는다.
- 자동 판정과 사람 판정을 따로 센다.
- 정답지 사람 검토 전 결과와 후 결과를 따로 낸다.
- `review.csv` 검토 순서: 1순위 누출 플래그, B·C인데 답함, 인용 실패 / 2순위 A 오답·놓침
